# highlight-cutter

## まず、普通の言葉で説明すると

アダルト動画って、1〜2時間もあるのに、本当に激しい場面はほんの数カ所だけ、ということが多いですよね。このツールは、その場面を先に見つけて切り出し、必要なら1本のハイライト版にまとめます。シークバーをドラッグして、自分で早送りしながら探さなくて済みます。

一番激しい場面の探し方は2通りあります。

- **動画に funscript が付いている場合は、それを読みます。** funscript というのは、平たく言うと「リモコンで動かせる電動オナホールへの指示書」です。動画の何秒目に、どう動いて、どれくらいの強さで動くかが書いてあります。このツールはその指示書を見て、動きが一番ぎっしり詰まっていて、一番強いところを選びます。
- **funscript がない場合は、音を聞きます。** 音声トラックを最初から最後まで聞いて、一番音が大きい区間を選びます。多くの動画では、一番うるさいところが、だいたい一番激しいところでもあります。

処理は全部、自分のパソコンの中だけです。動画がどこかにアップロードされることはなく、アカウントも API キーも要りません。

## インストール

Python 3 と ffmpeg（ffprobe 付き）が PATH にあればOKです。スクリプトは Python 標準ライブラリしか使いません。

```bash
# Debian / Ubuntu
sudo apt install ffmpeg
# macOS
brew install ffmpeg
# Windows
winget install ffmpeg
```

## 使い方

```bash
# auto：funscript があればそれを使い、なければ音声
python3 cut.py movie.mp4

# モード固定、上位5件、前後に5秒ずつ余白
python3 cut.py movie.mp4 --mode script --top 5 --pad 5

# クリップを1本のハイライトに連結もする
python3 cut.py movie.mp4 --concat -o highlights/
```

出力先は `<動画名>_highlights/`（または `-o` のフォルダ）です。

- `movie_clip01_123s.mp4` など——切り出したクリップ
- `movie_highlights.mp4`——`--concat` のときだけ、全クリップを連結したもの
- `clips.json`——各区間の開始・終了・長さ・スコア・モード。検出をやり直さずに再カットや後処理ができます

## パラメータ

| フラグ | デフォルト | 説明 |
| --- | --- | --- |
| `--script` | 動画と同名 | funscript が動画の隣にない場合のパス指定 |
| `--mode` | `auto` | `auto` / `script` / `audio`。auto は `.funscript` があればスクリプト、なければ音声 |
| `--top` | 5 | ハイライトを何区間取るか |
| `--pad` | 5 | 各区間の前後に足す余白（秒） |
| `--merge-gap` | 30 | 区間同士の間隔がこの秒数未満なら1つに結合 |
| `--concat` | off | クリップを1本のハイライトに連結する |
| `-o` | `<動画名>_highlights` | 出力フォルダ |

## 採点の仕組み

両モードとも10秒ウィンドウを1秒ずつスライドさせます。スクリプトモードのスコアは「位置変化の合計＋アクション数ボーナス」、音声モードは「RMS 音量の合計」です。その後、最強のウィンドウを貪欲に取り、`--merge-gap` 秒以内のものを無視して、`--top` 件そろうまで繰り返します。余白を足した結果近づいた区間は結合されます。

クリップの切り出しはストリームコピーではなく**再エンコード**（libx264 + AAC）です。これは意図的です。ストリームコピーはキーフレームでしか切れないので、「ハイライト」が数秒手前の前のシーン途中から始まることがあります。再エンコードならスコアが指した位置で正確に切れます。代償は速度です。

## 制限

- **激しい＝面白い、ではありません。** 拾うのは「一番忙しい／うるさい」瞬間です。本番のこともあれば、口論やカメラを落とした場面のこともあります。2時間を10分に絞る道具で、最終判断は自分でどうぞ。
- **スコアはその動画内での相対評価です。** 静かな動画でも top 5 は出ますが、それは「その中ではマシな部分」にすぎません。デフォルトを盲信せず、動画ごとに `--top` と `--merge-gap` を調整してください。会話中心の動画はスクリプトモードが無難で、音楽主体の動画は音声モードを簡単にだませます。
- **再エンコードは遅いです。** 2時間の 1080p ソースを切るには時間がかかります。走らせたらお茶でも淹れてください。
- 音声モードには音声トラックが必要です（当たり前ですが、無音の画面録画は実在します。その場合は推測せずエラーで止まります）。

## テスト

テスト素材は全て合成です（ffmpeg のテストパターン＋サイン波バースト、実写なし）。`tests/run_tests.py` で、両モードが仕込んだ3つのバーストを検出できること、クリップファイルと `clips.json` が一致すること、`--concat` で連結版が出ることを検証しています。記録は `tests/RESULTS.md` にあります。
