# highlight-cutter

## 일단 쉬운 말로 설명하면

성인 영상은 한두 시간씩 하는 경우가 많은데, 정작 가장 격한 장면은 몇 구간뿐일 때가 많습니다. 이 도구는 그 구간들을 먼저 찾아 잘라 내고, 원하면 하나의 하이라이트 영상으로 이어 붙여 줍니다. 재생 바를 이리저리 끌면서 직접 찾을 필요가 없습니다.

가장 격한 구간을 찾는 방법은 두 가지입니다.

- **영상에 funscript가 있으면 그 파일을 읽습니다.** funscript는 쉽게 말해 원격으로 조종할 수 있는 전동 자위 기구에 주는 '동작 설명서'입니다. 영상이 몇 초일 때 어떻게, 얼마나 세게 움직일지가 그 안에 적혀 있습니다. 이 도구는 그 설명서를 보고 동작이 가장 촘촘하고 강한 구간을 고릅니다.
- **funscript가 없으면 소리를 듣습니다.** 오디오 트랙 전체를 훑어서 가장 소리가 큰 구간들을 고릅니다. 많은 영상에서는 가장 시끄러운 곳이 곧 가장 격한 곳이기도 합니다.

모든 작업은 내 컴퓨터 안에서만 이뤄집니다. 영상이 어디에도 업로드되지 않고, 계정이나 API 키도 필요 없습니다.

## 설치

Python 3와 ffmpeg(ffprobe 포함)가 PATH에 있으면 됩니다. 스크립트는 Python 표준 라이브러리만 씁니다.

```bash
# Debian / Ubuntu
sudo apt install ffmpeg
# macOS
brew install ffmpeg
# Windows
winget install ffmpeg
```

## 사용법

```bash
# auto: funscript가 있으면 그걸로, 없으면 오디오로
python3 cut.py movie.mp4

# 모드 고정, 상위 5개, 앞뒤로 5초씩 여유
python3 cut.py movie.mp4 --mode script --top 5 --pad 5

# 클립들을 하나의 하이라이트로 이어붙이기까지
python3 cut.py movie.mp4 --concat -o highlights/
```

출력은 `<영상명>_highlights/`(또는 `-o` 폴더)에 생깁니다.

- `movie_clip01_123s.mp4` 등 — 잘라낸 클립들
- `movie_highlights.mp4` — `--concat`일 때만, 전체 클립을 이은 파일
- `clips.json` — 각 구간의 시작, 끝, 길이, 점수, 모드. 검출을 다시 돌리지 않고 재편집이나 후처리가 가능합니다

## 파라미터

| 플래그 | 기본값 | 설명 |
| --- | --- | --- |
| `--script` | 영상과 같은 이름 | funscript가 영상 옆에 없을 때 경로 지정 |
| `--mode` | `auto` | `auto` / `script` / `audio`. auto는 `.funscript`가 있으면 스크립트, 없으면 오디오 |
| `--top` | 5 | 하이라이트 구간 개수 |
| `--pad` | 5 | 각 구간 앞뒤에 더할 여유(초) |
| `--merge-gap` | 30 | 구간 간격이 이 초수보다 가까우면 하나로 합침 |
| `--concat` | off | 클립들을 하나의 하이라이트 파일로 합치기 |
| `-o` | `<영상명>_highlights` | 출력 폴더 |

## 채점 방식

두 모드 모두 10초 윈도우를 1초씩 슬라이딩합니다. 스크립트 모드의 점수는 '위치 변화 총합 + 액션 개수 보너스', 오디오 모드는 'RMS 볼륨 합계'입니다. 그다음 가장 강한 윈도우를 탐욕적으로 고르고, `--merge-gap` 초 이내의 것은 무시하면서 `--top`개가 찰 때까지 반복합니다. 여유를 붙인 뒤 가까워진 구간은 합쳐집니다.

클립 절단은 스트림 복사가 아니라 **재인코딩**(libx264 + AAC)입니다. 의도한 선택입니다. 스트림 복사는 키프레임에서만 자를 수 있어서 '하이라이트'가 몇 초 앞의 이전 장면 중간부터 시작할 수 있습니다. 재인코딩은 점수가 가리킨 위치에서 정확히 자릅니다. 대가는 속도입니다.

## 한계

- **격하다 ≠ 재밌다.** 이 도구가 찾는 건 '가장 바쁘거나 시끄러운' 순간입니다. 본 장면일 때도 있고, 말싸움이나 카메라 떨어뜨린 장면일 때도 있습니다. 두 시간을 십 분으로 좁혀 주는 도구이고, 최종 판단은 직접 하셔야 합니다.
- **점수는 그 영상 안에서의 상대 평가입니다.** 조용한 영상도 top 5는 나옵니다. 다만 '그중에서 덜 조용한 부분'일 뿐입니다. 기본값을 맹신하지 말고 영상마다 `--top`과 `--merge-gap`을 조정하세요. 대사 중심 영상은 스크립트 모드가 안전하고, 음악 위주 영상은 오디오 모드를 쉽게 속입니다.
- **재인코딩은 느립니다.** 두 시간짜리 1080p 소스를 자르는 데 시간이 걸립니다. 돌려놓고 차나 한잔 하세요.
- 오디오 모드는 오디오 트랙이 필요합니다(당연한 얘기지만 무음 화면 녹화도 실제로 존재합니다. 그 경우 추측하지 않고 오류로 멈춥니다).

## 테스트

테스트 소재는 전부 합성입니다(ffmpeg 테스트 패턴 + 사인파 버스트, 실사 없음). `tests/run_tests.py`가 두 모드 모두 심어 둔 세 개의 버스트를 찾아내는지, 클립 파일과 `clips.json`이 일치하는지, `--concat` 결과물이 나오는지 검증합니다. 기록은 `tests/RESULTS.md`에 있습니다.
